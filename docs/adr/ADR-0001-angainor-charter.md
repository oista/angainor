# ADR-0001: Устав Angainor — назначение и границы

**Статус:** Proposed  
**Дата:** 2026-11-09

## Контекст

Каркас проектов (структура репозитория, конфигурация, логи, тесты, CI, ADR, проверки архитектуры) уже сложился в PRODATA, moex-data-model, Clavis и Norma, но существует в нескольких расходящихся копиях: три реализации проверки ADR, три копии контракта конфигурации, два формата ADR, две независимые реализации исполняемых инвариантов. Новый проект начинается копированием вручную.

## Решение

- **Назначение:** Angainor — канон практики разработки и его воплощение: шаблон проекта, схемы форматов, проверки. Главный читатель — ИИ-агент, пишущий код, и инженер, который его проверяет.
- **Отдельный репозиторий**, не пакет Norma. Norma — общий слой времени работы (токены, агентский рантайм, коннекторы); Angainor — правила и проверки времени разработки.
- **Пользователь пока один.** Пакеты ставятся по git-тегу, без публикации в PyPI.
- **Входит:** `docs/canon/` (правила), `templates/` (будущий шаблон copier), `schemas/` (форматы), `scripts/` (проверки), позже — ядро проверок, вынесенное из `platform_archpolicy` PRODATA.
- **Не входит (non-goals):** сервер и интерфейс (сводка — модулем PRODATA); онтология (Clavis); метамодель данных (moex-data-model); runtime-контроль продуктовых агентов (ENTAN, по образцу Microsoft AGT); обмен с EA-инструментами и ArchiMate.
- **Потребители:** PRODATA, moex-data-model, Clavis, Norma; далее ENTAN и новые проекты.

## Последствия

**Плюсы:**

- Одна реализация каждой проверки вместо копий.
- Новый проект получает каркас из шаблона, а не копированием.

**Минусы и риски:**

- Изменение канона затрагивает все проекты — нужна дисциплина версий и `copier update`.

## Рассмотренные варианты

| Вариант | Почему отклонён |
| --- | --- |
| Пакет внутри Norma | Norma ничего не знает о продуктах и задаёт меру времени работы; правила разработки — другой ритм изменений и другой читатель |
| Восемь репозиториев (исходная концепция) | на одного человека — восемь CI и матрица совместимости; делить, когда разная скорость изменений появится на деле |
| Не выделять, вести каноны в каждом проекте | уже привело к трём расходящимся копиям проверок |

## Подтверждение

Вручную на ревью; связи канона, шаблонов и схем — `scripts/check_canon_links.py`.
