# ADR-0004: Хуки, навыки и плагины — формы правила, а не отдельные реестры

**Статус:** Accepted  
**Дата:** 2026-11-10

## Контекст

ADR-0003 ввёл реестр правил и проекции для Cursor, но оставил открытым, где описывать исполняемую часть: хуки (`normalize-plan-name.ps1` в трёх проектах), процедуры по фразе («зафиксируй», «проверь CI») и упаковку всего этого для проекта. Отдельные реестры хуков, навыков и плагинов дублировали бы идентификаторы, режимы включения и профиль проекта и снова позволили бы расходиться копиям.

## Решение

1. **Источник один — правило в `rules/`.** Хук, навык и плагин не имеют своих реестров, идентификаторов и переключателей; включает и выключает их профиль проекта вместе с правилом.
2. **Хук — поле `enforce` в шапке правила.** Это список привязок: `event` (событие агента), `tool` (скрипт из `tools/` Angainor), необязательные `matcher`, `args`, `timeout`, `fail` (`open` по умолчанию). В `args` подставляется `{project}`. Код хука — Python (LAY-4) в `tools/`. Если у правила есть `enforce`, в `check` указывается тот же инструмент или более полная проверка.
3. **Проекция хуков (Cursor).** `build_rules.py` копирует инструменты включённых правил в `.cursor/hooks/angainor/` с пометкой «generated» и пересобирает записи в `.cursor/hooks.json`. Чужие записи сохраняются; записи Angainor (команда содержит `.cursor/hooks/angainor/`) идут первыми и перезаписываются целиком. Выключенное правило убирает свой хук, а устаревшие копии инструментов сборка показывает как «лишний сгенерированный файл».
4. **Fail-open по умолчанию.** Ошибка хука не должна ломать работу агента: инструмент всегда завершается с кодом 0. Блокирующий режим (`fail: closed`) допустим только для правил с `norm` и описывается в самом правиле.
5. **Навыки — вторая проекция правил `on_request`, не отдельный источник.** Процедуры вида «зафиксируй», «проверь CI», «перед PR» остаются правилами; для Cursor они проецируются в `.mdc` (как сейчас), для Claude Code позднее — в `SKILL.md`. Каталог `skills/` в Angainor зарезервирован для процедур самого фреймворка (например, «подключи проект»), которые не являются проектными правилами; пока он не создаётся.
6. **Плагин — упаковка, а не исходник.** Готовый комплект правил, хуков и навыков проекта собирается из реестра в `dist/<проект>/` и не правится руками. Исходников плагина в репозитории нет.
7. **Объём первого шага — только Cursor.** Цели Claude Code (`settings.json`, `SKILL.md`, плагин) и `dist/` добавляются позднее как новые проекции без изменения источника. Для этого шапка правила не привязывается к формату Cursor: имена событий — из набора, общего для агентов, и схема допускает расширение.

## Последствия

**Плюсы:** одно место для правки логики хука; проекты перестают держать копии `.ps1`; правила, хуки и проверки идут вместе и видны в матрице; Claude Code добавляется генератором.

**Минусы и риски:** проектный `hooks.json` теперь частично генерируемый; хук запускается командой `python`, поэтому Python должен быть в `PATH` проекта; события Cursor меняются, и перечень в схеме придётся обновлять.

## Подтверждение

`scripts/check_rules.py` проверяет, что инструмент из `enforce` существует и что `matcher` задан только для событий инструментов. `scripts/build_rules.py --check` ловит расхождения `hooks.json` и копий инструментов. Тесты — `tests/test_rules_registry.py`, `tests/test_plan_name_hook.py`.

## Рассмотренные варианты

- **Отдельные каталоги `hooks/`, `skills/`, `plugins/` как источники.** Отклонено: дублирует идентификаторы и профиль, копии расходятся.
- **Хуки на PowerShell.** Отклонено: привязка к Windows (LAY-4); допускается только тонкая обёртка.
