# 09.004 Термины, определения и глоссарий

Как у элементов модели появляются определения и откуда берётся глоссарий.

**Правила:** [DM-4](../09-data-model.md), [DM-5](../09-data-model.md), [DM-9](../09-data-model.md), [DOC-4](../07-docs-adr.md)  
**Опора:** ISO 704 (принципы терминологической работы) и ISO 1087 (словарь терминологии); ISO/IEC 11179 (контекст определения); SKOS — представление глоссария; ADR-024, ADR-025, ADR-027 moex-data-model; ADR-0014 Clavis.

## Назначение

Определение — главная часть элемента модели: без него название ничего не объясняет ни человеку, ни агенту. Глоссарий не ведётся отдельно: это вид на определения модели, собранный автоматически. Поэтому глоссарий не может разойтись с моделью.

## Состав

| Понятие | Что это | Где хранится |
| --- | --- | --- |
| Термин (обозначение) | как элемент называется | `name`, `title`, `aliases` |
| Определение | единственное эталонное определение элемента на его уровне | `description` (элементы с `HasDefinition`) |
| Контекстное определение | дополнительный смысл в конкретном контексте; вне контекста не действует | `scoped_definitions` (`scope_kind`, `scope_ref`, `text`) |
| Источник определения | откуда унаследован или адаптирован текст | `definition_source_ref` |
| Глоссарий | вид на определения, а не набор данных | генерируется |
| Термин корпоративного глоссария | запись внешнего корпоративного глоссария | `GlossaryTerm` в реестре; назначается через `glossary_term_refs` |

Три вида глоссария (ADR-025):

- **онтологический** — классы онтологии Clavis, публикация в SKOS;
- **модельный** — понятия и сущности решений: это и есть глоссарий приложения;
- **корпоративный** — внешний мастер-глоссарий.

## Связи

**Каскад определения** — какое определение действует для элемента (ADR-025):

1. есть контекстное определение для нужного контекста — оно;
2. иначе своё `description`;
3. иначе унаследованное по `definition_source_ref`: от онтологии — только при точном соответствии (`exact`, `equivalent`); при `close`, `broad`, `narrow` нужно своё определение.

Действующее определение вычисляется и обратно в YAML не записывается.

```text
класс онтологии (только точное соответствие) ──► понятие ──► логическая сущность
корпоративный глоссарий ───────────────────────►   │              │
                                                   │              ▼
                                                   │   контекстное определение (решение)
                                                   ▼
                                       выгрузка в каталог данных, глоссарий
```

**Отношения между терминами** (ADR-027):

| Вид | Смысл | Как выражается |
| --- | --- | --- |
| Иерархия | вид — род | `parent_concept_ref`, подклассы |
| Эквивалентность | синоним, точное соответствие | `aliases`, `match_kind: exact` |
| Ассоциация | «см. также» — симметрично и не транзитивно | связанные термины, не дерево |

## Как оформлять

Определение по ISO 704: **родовое понятие + отличительный признак**.

1. Начинайте с ближайшего родового понятия: «Организация, которая…», «Запись, которая…».
2. Назовите признак, который отличает понятие от соседних того же рода.
3. Не повторяйте название и не определяйте через само понятие.
4. Без перечислений «и т. п.» и без описания того, как это хранится.
5. Одно основное предложение; пояснения и примеры — отдельной фразой.
6. На русском обязательно; английский желателен.

| Плохо | Почему | Лучше (учебный пример) |
| --- | --- | --- |
| «Юридические лица (ЮЛ)» | повтор названия | «Организация, зарегистрированная в установленном законом порядке, которая от своего имени приобретает права и несёт обязанности» |
| «Идентификатор ЮЛ» | повтор названия | «Неизменяемый идентификатор золотой записи юридического лица в MDM, присваиваемый при её создании» |
| «Клиент и т. п.» | нет рода и признака | «Сторона, с которой биржа состоит в договорных отношениях по оказанию услуг» |

**Глоссарий приложения.** Предметные термины — сгенерированный модельный глоссарий: ссылка на него стоит в `docs/glossary.md`. Руками в `docs/glossary.md` — только технические термины, которых нет в модели (DOC-4).

## Как проверяется

- Clavis: гейт ADR-0014 — у каждого `skos:Concept` есть `skos:definition`.
- DAMS: наличие `description` у элементов с определением; каскад определений в просмотрщике.
- Пока не проверяется: определение не повторяет название, не определяет через себя; глоссарий приложения собран из модели.

## Как сейчас

- Корпоративная концептуальная модель: у 81 из 82 понятий настоящее определение.
- Пакеты решений: у 232 из 234 элементов определение совпадает с названием.
- ADR-024 и ADR-027 moex-data-model — в статусе Proposed.
- В PRODATA, Clavis и Norma глоссарии ведутся руками в `docs/glossary.md`.
