# Angainor — концепция

**Architecture Governance And Integrity Norms — Oversight Registry.** Состояние на 09.11.2026.

Angainor — канон практики разработки и его воплощение для проектов экосистемы (PRODATA, ENTAN, Clavis, Norma, moex-data-model и новых): правила, шаблон проекта, схемы форматов и проверки. Главный читатель — ИИ-агент, который пишет код, и инженер, который его проверяет. Решение — [ADR-0001](adr/ADR-0001-angainor-charter.md).

## Принципы

- **Документация как код.** Всё — Markdown и YAML в git, меняется в том же PR, что и код.
- **Решение → правило → проверка.** У архитектурного решения есть ADR, у ADR — исполняемая проверка; решение без проверки — пожелание.
- **Извлекать, а не изобретать.** В канон попадает то, что уже работает хотя бы в одном проекте или закрывает реальный сбой.

Позже — ядро проверок, вынесенное из `platform_archpolicy` PRODATA, и инструменты для агентов (проверка плана до кода, разбор нарушения с подсказкой исправления).

## Что не входит

Сервер и интерфейс (сводка будет модулем PRODATA); онтология (Clavis); метамодель данных (moex-data-model); контроль продуктовых агентов во время работы (ENTAN, по образцу Microsoft Agent Governance Toolkit); обмен с EA-инструментами и ArchiMate.

## Как развивается

Дорожная карта — фазы с воротами: канон практики → ядро проверок из PRODATA → шаблон и четыре проекта-потребителя → агентный контур → каталоги и пресеты → v1.0. Детали — в документе «Angainor — аудит, аналоги и дорожная карта».

## Идеи из исходной концепции, отложенные до своих областей

Исходная концепция (сентябрь 2026) лежит в [archive/](archive/). Её устройство заменено каноном, но эти мысли стоит развить, когда до них дойдёт очередь; каждая станет областью канона только вместе с работающей практикой.

| Идея | Куда |
| --- | --- |
| Метрики: DORA; метрики агентных систем — задержка вызова, стоимость запроса, доля успешных вызовов инструментов, частота эскалаций человеку; метрики архитектурного здоровья — нарушения проверок во времени, просроченные ADR | будущая область «Метрики»; часть уже собирает PRODATA |
| Плановые архитектурные ревью: по областям, со списком вопросов, с периодичностью | будущая область «Ревью»; сначала правило, потом шаблон |
| Модель угроз STRIDE для каждого сервиса | будущая область «Безопасность» |
| Политика агентов: разрешения на инструменты, случаи обязательного подтверждения человеком | `AGENTS.md` и будущая область «Агенты» |
| Фитнес-функции производительности (пороги задержки как тесты) и эволюционные (рост связности и сложности во времени с предупреждением) | развитие ARC-1 |
| После развёртывания — проверка работоспособности с откатом при провале | развитие CI-6 |
| Реестр паттернов и подходов: каталог + фиксация выбранного в проекте, сводка «какой паттерн где» по всем репозиториям | фаза каталогов и пресетов |
| Радар технологий (adopt / trial / assess / hold) на уровне экосистемы | фаза каталогов и пресетов |
| Пресеты по типу проекта: агентный сервис, платформа данных, сервис онтологий, общая библиотека, модель данных | фаза каталогов и пресетов |
